# 交付形态与自检清单

## 只交付成品

正式文档只要能直接使用的成品。以下内容一律不写入正文，也不作为附件清单：

- 用途、编制日期、依据材料、核验说明、核验等级及释义、待核条目、清稿提醒；
- 会谈备忘、话术与时段安排、留档清单、内部校核意见；
- 结尾免责声明、AI 生成标记、水印、「本报告……」式自我指代；
- 任何解释「这份材料怎么用、怎么核、还差什么」的态度辅助性文字。

无法核实的内容直接不写入正文，不用「需人工核实」占位。来源目录只列文件名称、文号、发文机关、日期、官方链接，不评级。

聊天回复同样不写「需要的话我可以……」式收尾，不写自我检讨式铺垫。

## 交付前机械自检

`scripts/verify_report.py` 逐项检查，任一失败即不得交付。

| 类别 | 检查项 |
|---|---|
| 结构 | XML 合法；A4 与页边距已写入；表格数、行数与源稿一致；超链接数量与来源条目一致 |
| 版式 | 全表行 `cantSplit`、表头 `tblHeader`、末行断链、表题 `keepNext`；三线表无彩色 |
| 渲染 | 主标题在 PDF 中为单行；每张表的所有行落在同一页；无空白页 |
| 元数据 | `docProps/custom.xml` 不含 AIGC 标记 |
| 标题 | 全部标题无逗号句号、无禁用情态词、无判断句、无「结论／摘要」章名；层级序号一致 |
| 用词 | 无套话、无 buzzword、无 emoji、无 Markdown 标记、无辅助性文字 |
| 内容 | 无空节（每个标题下正文长度足够）；交叉引用指向现存章节；关键文号与来源齐全 |

## 生成链路

```
Markdown 中间稿
  → scripts/build_report.py       正式排版 HTML（主标题字号自动计算）
  → WorkBuddy html-to-doc 转换    DOCX
  → scripts/fix_docx_layout.py    A4、三线表、不跨页链、清除 AIGC
  → scripts/ensure_tables_on_one_page.py   渲染实测 + 跨页自动修复 + 复测
  → scripts/verify_report.py      全量校验
```

用 `scripts/make_docx.py <input.md> <output.docx>` 一次跑完。渲染依赖 `aspose-words`（Word 布局）与 `pymupdf`（页内文本提取）；缺失时校验脚本必须报错，不得静默跳过。

## Word 视图辅助符号排障

Word 有三个互相独立的视图开关，常被误认为文档缺陷。三者都不进入打印与 PDF，文档本身无需修改。

| 屏幕现象 | 对应开关 | 恢复路径 |
|---|---|---|
| 行首 `·`、标题末尾蓝色 `↵`／`¶` | 显示所有格式标记 | Mac `⌘+8`；Windows `Ctrl+Shift+8`；或「开始」→ `¶`；Mac 偏好设置 → 视图 → 显示 |
| 上一页末行与下一页首行紧贴，中间只剩一条细横线 | 在打印布局视图中显示页面间空白（被关闭） | Mac：**Word → 偏好设置 → 视图 → 勾选 `White space between pages in Print Layout View`**；Windows：文件 → 选项 → 显示 → 勾选「在页面视图中显示页面间空白」；或把鼠标移到两页之间那条细线上，光标变双箭头时**双击** |
| 横线两端的小方块 | 裁剪标记 `Crop Mark`（被开启） | Mac：Word → 偏好设置 → 视图 → 取消 `Crop Mark` |

关键区分：关掉 `¶` 之后页面仍然贴合，是因为第二个开关独立存在，不是没有生效。用户说「两块内容连在一起」「分页看不到」时，先查页间空白，不要再去改文档。

另需区分内容层面：长文件名与后续引文在正文中本就属于同一段落，首行缩进与自动换行会让文件名恰好落在页末一行，看起来像独立标题。这属于正文写法，不是显示设置；如要独立成段，须改 Markdown 源稿并重新生成，不以屏幕辅助符号为依据。

判断文档是否干净，以 `verify_report.py` 的逐段 XML 检查与渲染实测为准，不以编辑器屏幕为准；不得据屏幕辅助符号改写正文或重新生成文件；不得把 Aspose 免费版带评估水印的 PDF 当作交付件。

## 交付物

- 主交付：`.docx` 正式成品。
- 可选附：同名 `.md` 源文件（含完整链接，便于核对与二次编辑）。
- 不交付：PDF 校验副本、HTML 中间稿、检查日志（这些留在 `/tmp`）。
